## 1. ARQUITETURA E CÓDIGO
------------------------------------------------------------

### Problemas Atuais

- Módulos em modules/ nunca são integrados ao CommandRegistry
- Comandos hardcoded em jarvis.py (God class)
- CommandRegistry aceita apenas Callable sem argumentos
- MEMORY_ROOT hardcoded como Path("E:\\JARVIS_MEMORY")
- Modelo de chat fixo (llama-3.3-70b-versatile) sem vir de settings

### Ideias de Melhoria

- [ ] Plugin system real: ModuleManager deve registrar comandos automaticamente
- [ ] Comandos com args: parsing de argumentos (ex: search --cat projects python)
- [ ] Settings centralizado: mover GROQ_API_KEY, MEMORY_ROOT, CHAT_MODEL para Settings
- [ ] Injeção de dependência: usar protocolos/dataclasses para desacoplar Jarvis
- [ ] God class split: extrair _cmd_* methods de jarvis.py para módulos separados


## 2. FUNCIONALIDADES
------------------------------------------------------------

### O que falta

- [ ] Argumentos em comandos: search python, remember "texto", forget abc123
- [ ] Histórico de comandos: navegar comandos anteriores com setas
- [ ] Autocomplete/Tab completion: sugerir comandos ao digitar
- [ ] Comando config: ver/editar configurações em runtime
- [ ] Comando model: trocar modelo de IA em runtime
- [ ] Comando history: ver histórico de conversas
- [ ] Comando export/import: exportar/importar memórias
- [ ] Multi-provider: suportar OpenAI, Anthropic, local models além de Groq
- [ ] RAG com memória: injetar memórias relevantes no contexto do chat
- [ ] Scheduled tasks: tarefas agendadas (cron-like)
- [ ] Shell commands: executar comandos do SO (!ls, !dir)


## 3. UX / INTERFACE TERMINAL
------------------------------------------------------------

### Problemas

- help está hardcoded em 3 lugares
- Mensagens de erro genéricas
- Sem feedback visual de processamento (loading spinner)
- Sem diferenciação visual entre tipos de saída
- Prompt fixo sem indicador de status

### Ideias

- [ ] Prompt dinâmico: [jarvis v0.1.0 | groq | 42 memórias] >
- [ ] Loading indicator: spinner durante chamadas API
- [ ] Tab completion: usar prompt_toolkit ou readline
- [ ] Cores contextuais: erros vermelho, warnings amarelo, info ciano
- [ ] ASCII art banner mais elaborado no startup
- [ ] Command aliases: s -> search, r -> remember, m -> memory


## 4. MEMÓRIA E IA
------------------------------------------------------------

### Problemas

- Sem RAG: chat não consulta memórias para respostas contextualizadas
- should_save() usa keywords hardcoded sem classificação inteligente
- _cmd_remember() classifica manualmente em vez de usar o LLM
- Busca é apenas substring match sem embeddings

### Ideias

- [ ] RAG pipeline: buscar memórias relevantes antes de cada response
- [ ] LLM-based classification: usar modelo para classificar/importâncias
- [ ] Semantic search: embeddings + cosine similarity
- [ ] Conversation memory: salvar e recuperar conversas completas
- [ ] Memory context injection: system prompt dinâmico com memórias relevantes
- [ ] Auto-summary: resumir conversas longas e salvar como memória
